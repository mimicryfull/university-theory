## Статус і пріоритет вимог

Це робочі правила нашого шаблону для ЛНУ імені Івана Франка, факультету
електроніки та комп’ютерних технологій, групи ФЕІ-34с. Це **не затверджена
університетом форма** і не заява про відповідність усім вимогам ДСТУ.

Порядок пріоритету: прямі вказівки користувача → вимоги викладача й методичка
конкретної лабораторної → ці базові правила. Якщо матеріали суперечать одне
одному і це впливає на оцінювання, уточнити суперечність.

На 14.10.2026 у перевірених відкритих матеріалах не знайдено єдиних правил
оформлення для всіх лабораторних факультету. Вимоги до курсових і дипломних
не переносити автоматично на лабораторні.

## Базове оформлення

Параметри нижче — обрані налаштування шаблону, не підтверджені факультетські норми.
Їхні значення зберігаються окремо в `rules.typ`.

| Елемент | Налаштування |
| --- | --- |
| Аркуш | А4, книжкова орієнтація |
| Поля | ліве 30 мм, праве 15 мм, верхнє та нижнє 20 мм |
| Основний текст | Literata, 14 pt, чорний, українська мова |
| Звичайні рядки | крок базових ліній 21 pt, тобто 1,5 від 14 pt |
| Абзац | відступ 12,5 мм, вирівнювання за шириною, без додаткового інтервалу |
| Заголовки | 14 pt, напівжирні, зліва, автоматична нумерація 1, 1.1 |
| Номери сторінок | унизу по центру; титульна враховується як 1, номер прихований |
| Код | MonoLisaCode, 10 pt; світла підсвітка синтаксису `code-light.tmTheme` |
| Таблиці та підписи | 12 pt, компактний міжрядковий інтервал |
| Ілюстрації | наскрізні номери, підпис «Рисунок N — Назва» знизу |
| Таблиці | окрема наскрізна нумерація, підпис «Таблиця N — Назва» зверху |
| Формули | STIX Two Math; окремі формули мають автоматичні номери (1), (2), … |

Literata — шрифт, обраний користувачем і встановлений у цій системі.
Якщо вимога прямо вказує **Times New Roman**, встановити справжній шрифт
і задати `font: "Times New Roman"` у `rules.typ`. Не називати альтернативу
Times New Roman. Шрифти основного тексту й коду мають бути встановлені
в середовищі збірки. MonoLisaCode використовується з локальної установки;
його файли не поширюються в репозиторії. STIX Two Math поставляється в
`fonts/` разом із ліцензією SIL OFL 1.1; для CLI передавати
`--font-path fonts`. Цей шрифт має таблицю OpenType MATH для формул.
Код із вказаною мовою (`python`, `sh`, `json`) отримує підсвітку;
короткі inline-назви без мови зберігають MonoLisaCode й основний колір.

Для основного тексту в `template.typ` явно задано верхню й нижню межі рядка
`top-edge: 0.8em` і `bottom-edge: -0.2em` та проміжок 0,5 em.
У блоці «Виконав / Перевірив» використовувати явні переноси рядків усередині
абзацу, щоб зберігався той самий крок 21 pt.
Текст цього блока вирівнювати вправо до правого поля сторінки.
Між сусідніми абзацами задавати `spacing: 0.5em`: це забезпечує той самий
крок 21 pt на межі абзаців, без додаткової порожньої лінії.
Формули, код, таблиці й заголовки мають
свої параметри; не вимагати кроку 21 pt для всіх елементів документа.

Не ставити крапку наприкінці заголовка, не підкреслювати заголовки. Не набирати
відступи пробілами. Використовувати автоматичні номери й посилання Typst.

## Структура і зміст

1. Титульний аркуш.
2. Мета роботи відповідно до завдання.
3. Завдання, варіант і вихідні дані.
4. Стислі теоретичні відомості, якщо потрібні за методичкою або для пояснення.
5. Хід виконання: середовище, алгоритм, реалізація, пояснення ключових дій.
6. Результати та перевірка: фактичні дані, таблиці, графіки, скриншоти, аналіз.
7. Висновки, пов’язані з метою й отриманими результатами.
8. Контрольні запитання, джерела та додатки — коли потрібні.

Методичка може змінювати цей порядок. Зміст для короткого звіту вимкнений;
за потреби ввімкнути `with-outline: true`. Не додавати анотації, реферат і
структуру дипломної роботи лише заради обсягу.

Умова й мета мають відповідати наданому завданню. Не вигадувати вимоги або
додаткові обов’язкові розділи. Пояснювати код і результати стисло українською,
залишаючи назви команд, API, змінних і повідомлень програми в оригіналі.

## Результати, код та ілюстрації

- Виконувати доступні перевірки коду в реальному середовищі. Зберігати важливі
  вихідні дані й результат запуску поруч із матеріалами роботи.
- Відокремлювати очікуваний результат від фактичного. Якщо запуск або вимірювання
  не виконано, прямо зазначати це; не стверджувати, що тест пройдено.
- Не вигадувати вимірювання, скриншоти, логи, дати чи успішний захист.
- Для програмування включати доречні основні, граничні й помилкові випадки;
  для експериментів — одиниці вимірювання та похибки, коли цього вимагає робота.
- У тексті посилатися на рисунки й таблиці та пояснювати, що вони доводять.
  Скриншоти мають бути читабельними; прибирати зайві панелі й персональні дані.
- Довгі рядки коду переносити в самому коді без зміни його змісту: Typst `raw`
  не слід вважати засобом автоматичного перенесення всіх довгих рядків.
- Повний великий код виносити в окремий файл або додаток; у тексті залишати
  фрагменти, потрібні для пояснення, якщо викладач не вимагає іншого.
- Джерела зазначати лише реально використані, із точними назвами й адресами.
- Висновки формулювати за виконаними діями; не залишати універсальні фрази,
  які не описують конкретного результату.

## Підготовка наступної лабораторної

1. Прочитати умову, методичку та контекст; визначити дисципліну й викладача.
2. Скопіювати `lab.typ` у `lab-NN.typ`. Використовувати спільний `template.typ`.
3. Заповнити метадані, прибрати текст-підказки й демонстраційний код.
4. Виконати завдання, зберегти код і матеріали, додати перевірені результати.
5. Узгодити структуру з методичкою; заповнити контрольні відповіді за потреби.
6. Зібрати PDF, перевірити всі сторінки, нумерацію, шрифти, посилання,
   читабельність і відсутність обрізаного коду та незаповнених полів.
7. Передати `.typ`, PDF і код/матеріали. Вказати, що лишилося неперевіреним.

Не змінювати глобальні правила через вимогу лише однієї дисципліни без потреби:
для такої роботи створити окремий профіль оформлення або локальне перевизначення.
